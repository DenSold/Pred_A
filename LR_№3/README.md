В данном репозитории представлены следующие материалы:

## Реализованный функционал

### 1. Исследовательский анализ данных (EDA)

В рамках этапа анализа данных выполнены следующие действия:

* проверка структуры набора данных и оценка его качества;
* построение графиков временных рядов для каждого из городов;
* анализ распределений признаков (гистограммы, boxplot, Q-Q графики);
* сравнительное исследование температурных показателей и осадков между городами;
* вычисление и анализ корреляций;
* тестирование стационарности рядов (ADF-тест);
* выявление пропусков и обоснование подхода к их обработке.

---

### 2. Формирование признаков

Для повышения качества моделей были созданы дополнительные признаки:

* календарные характеристики;
* циклические преобразования (`sin` и `cos`);
* лаговые переменные;
* скользящие статистики;
* показатели динамики (изменение температуры, ускорение, темп изменения давления);
* климатическая норма и отклонение от неё;
* снижение размерности с использованием PCA для оценки разделимости классов.

---

### 3. Классификация климатического типа

Разработана модель для определения климатической категории на основе 30-дневного окна временного ряда.

Классы:

* **умеренно-континентальный**: Москва, Санкт-Петербург;
* **морской субтропический**: Сочи, Геленджик;
* **дальневосточный**: Благовещенск, Находка.

Используемый алгоритм:

* `RandomForestClassifier`, обученный на агрегированных признаках временного окна.

Оценка качества проводилась с использованием:

* Accuracy;
* Precision / Recall / F1 (macro и weighted);
* матрицы ошибок;
* ROC-AUC (One-vs-Rest);
* анализа ошибок по месяцам;
* permutation importance.

---

### 4. Прогнозирование временных рядов

Для каждого города формируется отдельный набор данных, после чего выбирается наилучшая модель по результатам валидации среди:

* `Ridge` (multi-output);
* `RandomForestRegressor`;
* `ExtraTreesRegressor`.

Цель — прогнозирование температуры (`temperature_2m`) на горизонте 30 дней.

Используемые метрики:

* MAE;
* RMSE;
* MAPE;
* WAPE;
* Direction Accuracy;
* диагностика остатков (Shapiro–Wilk, Ljung–Box, White test).

---

### 5. Комплексный пайплайн

Реализован класс `TwoStageWeatherPipeline`, объединяющий:

1. анализ последних 30 дней данных;
2. определение климатического типа;
3. выбор специализированной модели;
4. построение прогноза температуры на 30 дней.

## Интерпретация результатов

### EDA

Следует обратить внимание на:

* наличие трендов и сезонных компонент;
* различия между городами;
* характер распределений;
* структуру корреляций;
* выводы по стационарности рядов.

### Классификация

Ключевые показатели:

* Accuracy и F1_macro — основной ориентир качества;
* Confusion Matrix — анализ путаницы классов;
* ROC-AUC OvR — оценка уверенности модели;
* Permutation Importance — вклад признаков.

### Прогнозирование

Основные метрики:

* MAE и RMSE — абсолютные ошибки;
* MAPE и WAPE — относительные ошибки;
* Direction Accuracy — корректность направления изменения температуры.

### Анализ остатков

Интерпретация тестов:

* малое значение p-value в Ljung–Box — наличие автокорреляции;
* малое p-value в White test — возможная гетероскедастичность;
* малое p-value в Shapiro–Wilk — отклонение от нормальности.

Для климатических данных подобные эффекты допустимы; важнее устойчивость метрик и отсутствие систематического смещения.

## Дополнительные замечания

1. Прогнозирование реализовано в daily-формате для горизонта 30 дней.
2. Исходные данные почасовые, однако для долгосрочного прогноза суточная агрегация более устойчива.
3. Классификация выполняется по климатическому типу, а не по конкретному городу.
4. Используется стратегия выбора лучшей модели по валидации.
5. Возможные направления улучшения:

   * прогноз осадков;
   * вероятностные интервалы;
   * градиентный бустинг (CatBoost, LightGBM, XGBoost);
   * нейросетевые архитектуры (LSTM, Temporal CNN, Transformer);
   * ансамбли моделей.
